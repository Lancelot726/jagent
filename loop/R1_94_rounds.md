**触发**：`R1_00_req_product.in.txt`（作者愿景全文）。

**本轮着力点**：把愿景落成一个能在终端跑起来、且**设计理念可被肉眼观察**的 demo。

**范围**

  博弈论（密封拍卖选模型档位）、经济学（预算账本 + 压缩 ROI）、控制论（并发闭环与熔断）
- 外（推迟 R2）：进化论基因组、GraalVM native、分层流程图布局、终端 raw mode 行编辑

**关键决策**
| 决策 | 结论 | 理由 |
|---|---|---|
| 依赖 | 纯 JDK 零依赖 | native 编译、体积、启动速度的前提 |
| 并发 | 不用 `StructuredTaskScope` | Java 25 仍是 preview，锁死版本且拖累 native |
| 上下文 | `ScopedValue`（JEP 506 已转正） | 工具签名无需透传上下文，Java 相对 Go 的优势 |
| 离线可测 | `MockClient` 列为必需 | 无 key 也能演示，否则每次演示烧 token 且无法自测 |
| 流程目录 | 过程文件收进 `loop/` | 偏离 skill 的根目录平铺，理由见任务书 §流程适配 |
| 语言 | 两层：L1 内部固定英+缩略；L2 面向用户首启选 Zh/Eng | 提示词 `[]` 里是可选项而非常量；缩略只在英文成立 |

> 并给出 `chcp 65001` 处方。切 UTF-8 复跑即恢复正常。**产品侧零改动，266 断言基线不受影响。**
