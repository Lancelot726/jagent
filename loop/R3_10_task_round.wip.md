### 替换表（G1 已确认，2026-09-20）

| 现显示 | 改为 | 位置 |
|---|---|---|
| 机制对账 | `summary` | `score.title` |
| 对账单已写入 | `summary written to %s` | `score.saved` |
| 拍卖 | `picks` | `score.auction` 行首 |
| 中标 | `won` | `score.auction` 内 |
| 信誉 | `score` | `score.rep` 行首 |
| 预算 | `quota` | `score.budget` 行首 |
| 控制论 | `flow` | `score.gov` 行首 |
| 竞价 | `pick` | `run.bid` |
| 利润 | `net` | `run.credits` |

**做法**：键名与键集合**都不动**，只改值。
因该批标签属 L1（内部协议词汇，不随用户语言变），**令 `zh` 与 `eng` 两档该批取值相同**
——`eng.properties` 里已有现成的中性英文措辞，以它为准，只把其中仍带学科色彩的
`auction` / `reputation` / `budget` / `control` / `profit` / `bid` / `scorecard` 换掉。
这样对账单整块成为统一的 L1 文本，不再出现中英混排。

**实际执行时把范围扩到了整块**：作者只点名 9 个词，但这 9 个词分散在 `summary` 整块与 `run.*` 标签里，
若只换这 9 个，同一屏会出现「`picks` … `won` … 步数 … 预算」的中英混排。
故按「L1 就该整块固定英文」的层次原则，把 `graph.*` / `score.*` / `run.*` 这一整批**显示标签**
统一成英文（键名与键集合仍不动）。散文类（`run.usage` / `run.limit` / `run.abort` / `run.plan` /
`repl.hint` / `repl.bye` / `err.*`）**仍随 `--user-lang` 变**，保持中文。
**此点超出 G1 已确认的替换表，已在 G3 送审时请作者一并确认。**

### 2.3 编码后追加：步数上限改为配置项（作者 2026-09-20，**并入 R3**）

作者问「怎么让步数无上限」。查现状：上限是**两处写死的字面量** ——
根 agent `Cli` 传 `16`，子 agent `SpawnTool` 传 `8`；循环体为 `step <= maxSteps`，
跑满即 `graph.fail(root, "max steps")` 并返回 `null`，`Cli` 据此判为 `limit`。

**作者裁定（四项）**：

| 问 | 答 |
|---|---|
| 形态 | **加配置键** `max-steps` / `JAGENT_MAX_STEPS`，默认 16，设 `0`（或负数）表示不限 |
| 子 agent | **跟着一起放开**，与根共用同一个值（`SpawnTool` 透传） |
| 兜底闸 | **先不加**，只放开上限 |
| 轮次归属 | **并入 R3**（G1 追加 g），不新开轮 |

**实现要点**：新增 `Config.intAny`（`intOr` 会把 `<= 0` 当解析失败退回默认值，
故不能用它解析该键）；循环条件改为 `maxSteps <= 0 || step <= maxSteps`——
**不用 `Integer.MAX_VALUE` 当"无上限"**，因为 `step++` 会在该值处溢出为负数、
条件反恒真。

**已登记的风险（作者知悉并接受）**：撤掉上限后循环**唯一的出口是模型自己收尾**。
`Budget`（默认 40000 token）只记账并影响出价、`Governor` 的 `open` 跳闸标志
在 `Agent.run` 里**未被读取**，两者都不中止循环。故"不限步数"只承诺不给自设截止，
不承诺兜住不收敛的任务。该边界已写入 `docs/PROTOCOL.md` §7 与 `docs/DEMO.md` §4。

## 4 阻塞点（编码前须先解）

**4.1 摘要截断是两处叠加**（**已解**）

`Agent.java:254` 的 `summarize()` 先截 60 字符，`GraphView.java:76` 的 `clip()` 再截 48 字符。
只放宽 `clip` 不解决根因 —— 按本轮口径，正确做法是**取消这条链路**：
节点上不再写模型回复的长摘要，改由收尾统一总结输出。

**落地**：`Agent` 收尾节点 note 由 `summarize(t.content())` 改为固定标记 `answer`，
`summarize()` 随之删除（唯一调用点即此处）；`Cli.run` 在 `agent.run` 返回后打印
`run.answer` + **完整**回复（逐行 `dash.log`，不再截断）；`GraphView.clip` 48→60，
与 `Scheduler.note` 的 60 对齐，消除二次截断。

**边界**：工具节点的短结果（`wrote 11 bytes` 之类）保留。判据是"能否一行说完"，不是固定字数。

**4.2 标签的层次归属**

现状这六个词写在 `resources/lang/{zh,eng}.properties`，即 L2 —— 随 `--user-lang` 变。
按硬约定 #5 它们应属 L1。**最小改动**是保持键位、令两档取值相同；
**不动**的是代码类名（`Auction` / `Governor` 等）与键名本身。

**4.3 REPL 与现有命令入口的关系**（**已解**）

现状 `Cli.main` 是"解析 argv → 派发一次 → 退出"，**没有任何 stdin 循环**
（全库读 stdin 的只有 `Config.java:156` 首启选语言、以及未接线、未挂进工具表的 `HumanTool`）。

裁定：**不带参数启动即进 REPL**。故 `run(argv)` 在 `pos` 为空时转入循环，
而不是打印帮助退出。**风险**：现有无参数行为会变 —— README 已加
「不带参数启动即进交互式命令行」，帮助里新增 `cmd.repl` 一行，
新增断言 `R3T[8][9][10]` 覆盖读行循环。

**4.4 REPL 里的模式**（**已解，且已被 §2.1(b) 再收缩**）

作者原话：「提示符前面有一个 `[run]` 可以进入选择 默认是 run」。当时的解读是
「提示符 `[run] > `，可敲 `:chat` / `:run` 打字切模式，不做上下键」。

**该解读已作废**：作者随后取消 `chat`（§2.1a），REPL 只剩 run 一种模式，
故模式标记失去意义，作者明确「提示符前都不用加[run]」（§2.1b）。
**最终实现：提示符就是 `> `，无模式标记，无 `:chat` / `:run` 指令。**

`enter` 之外的可用指令只剩 `:help` / `help`、`:doctor` / `doctor`、`:q` / `exit` / `quit`、EOF。
未知 `:` 开头的指令按未知子命令报错但不退出循环（`R3T[10]`）。

**遗留**：作者早前提过的"上下键选择"随模式取消一并失去载体；
若将来要做历史/行内编辑，那是 `R4` 的 raw mode 项，与模式切换无关。
