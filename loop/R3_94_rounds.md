**关键决策**

| 决策 | 结论 | 理由 |
|---|---|---|
| 四项怎么装轮次 | **不并入 R2，整体新开 R3** | 三条属口径变化，逐条分治会让 R2 反复重开送审 |
| 标签改哪一层 | **只改终端显示文字** | 类名/键名一改则波及全套断言，收益与风险不成比例 |
| 换词幅度 | **只换最带学科色彩的九个** | 工具/步数/压缩/降级/执行图本来就中性，无需动 |
| 标签的层次归属 | 由 L2 移入 **L1**（固定英文） | 硬约定 #5：L1 是内部词汇，L2 才是面向用户散文；当初放错了层 |
| 标签执行范围 | **整批 `graph.*`/`score.*`/`run.*` 显示标签统一英文** | 9 词散在 summary 整块与 `run.*` 里，只换 9 词会出现中英混排；按"L1 就该整块固定英文"收口 |
| REPL 形态 | **基础版**（提示符 + 读一行跑一行） | 先把"能反复敲"做出来并固定住；raw mode 跨平台按键风险大，不宜并轮 |
| REPL 模式 | **无模式标记**，提示符即 `> ` | `chat` 取消后只剩 run，模式标记失去意义 |
| `chat` 去留 | **取消** | 它不读文件，行为与 run 重复；唯一的差异（显示思维链）不值得单独留一个入口 |
| 执行图承载 | **只画结构与状态**，回复改为末尾统一总结 | 图的本意是看结构与进度；把整段回复塞进节点，放宽上限也只是把问题推后 |
| 命令通道（追加） | **保持 `cmd`**，补环境事实 + 修掉卡死 | 换 PowerShell 会把问题从"缺信息"变成"换平台假设"，且默认策略仍会踩坑 |
| 记忆口径（追加） | **落盘回灌 + 会话内上下文，两条都要** | 两者失效方式不同：只做前者则同会话内看不见刚问过的那句，只做后者则一重启就失忆 |
| 剥离作用面（追加） | 只作用于**终端显示** | 对话上下文与 `work/` 保留模型原文，否则呈现修正会变成改写模型输出 |
| 总结触发面（追加） | 成功 / 失败 / 中止**都要有** | 「失败没总结」正是现场反馈里最刺眼的一条 —— 越是没有结果，越需要说清卡在哪 |
| 步数上限形态（追加 g） | **加配置键**，默认 16，`0` 表示不限 | 写死两处就要改码重编；既有的 `permits` / `budget` 都走这条路，跟着走即可 |
| 无上限的写法（追加 g） | **哨兵判断**，不用 `Integer.MAX_VALUE` | 后者 `step++` 会溢出为负，让 `step <= maxSteps` 反而恒真 |
| 子 agent 是否一并放开（追加 g） | **一并放开**，与根共用同一个值 | 作者裁定；`SpawnTool` 原本另有写死的 8，留着会造成两个上限口径 |
| 兜底闸（追加 g） | **本轮不加** | 作者裁定先只放开上限；已知 `Budget` 只记账、`Governor` 跳闸不中止循环，该边界已写进宪法修订 8 与 `docs/PROTOCOL.md` §7 |
| 总结块的去留（追加 h） | **整块删除**，收尾只留 `answer` 一段 | 作者已在现场否掉它：`answer` 已承担收尾，"再来一段总结"纯属同义重复；目标（说清结局）不减，只去载体 |
| 失败与中止怎么写（追加 h） | **并入 `answer` 段内** | 作者原话"失败也用 answer 回答"——若保留独立的失败块，就还是两处收尾；且失败时更该在同一个位置说清 |
| step 行怎么收敛（追加 h） | **保留三类过程行，只去噪声** | 作者要的正是"简单显示每一个 step 进度"；冒犯感来自 `pick` 行与整串 JSON 参数，不是来自过程行本身 |
| 工具参数怎么显示（追加 h） | **取一个键的值做摘要**，截 60 字符 | 终端要的是"在干什么"，`{"path":"demo/a.txt","content":"…"}` 里的正文对读屏无意义 |
| 对账块默认态（追加 h） | **默认不开**，`--scorecard` 才显示 | 竞价/配额/对账是机制自证，属运维视角；日常使用不需要，但演示与回归仍要能一键取回 |
| 关闭打印是否连记账一起关（追加 h） | **不关** | 与"剥离只作用于显示层"同口径：观感可以调，`work/scorecard.txt` 与 `work/runs.md` 的落盘不受影响 |
