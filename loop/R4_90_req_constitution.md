## 修订 1：项目定义去学科化（§1 的改写）

**背景**：R3 修订 1 曾把去学科化的作用面**限定在终端显示文字**，明确
"`README.md`、`docs/` 一律不动；`loop/` 过程文件里的学科表述保留"。

**修订（作者 2026-09-24 裁定）**：撤销上述边界。去学科化的作用面**扩展为全部说明性文本**，
即 `README.md`、`docs/`、`loop/` 下的过程记录与台账。作者原话：
"博弈论经济学、工程经济学、控制论…… 我希望……都把这个字眼改换成比较普适的
计算机工程和软件工程或者是 agent 的字眼"。

**§1 项目定义改写后**：

> 用 Java 25 实现**终端 CLI coding agent**（对标 Claude Code / Pi）。
> 差异化不在于"换语言重写"，而在于**把六条运行时机制做成可观察的工程实现**：
> 模型路由、资源管理、ROI 判定、自适应并发控制、执行图、自动化闸门
> **直接作用于运行时**，不是写在文档里的口号。

原表述里的"**方法论**"与"自适应演化"两项随之调整：前者改为"做成可观察的工程实现"，
后者自 R3 起已暂缓，不再列进 §1 的机制枚举（暂缓状态另见 `R3_94` 文末）。

**术语口径**：文档用词统一到计算机工程与 agent 通用说法，逐词映射见 `R4_10` §3。
作者明确**禁用「成本收益」**这一提法。

**边界（不改什么）**：

- 本条改的是**措辞**，不是**机制**。六条机制的行为、判定逻辑与证据（`R2_50` / `R2_51`）不变。
- **代码类名 / lang 键名 / 协议文件名 / 断言语义一律不动**——本轮不触碰任何运行时行为。
- 只读输入原稿 `loop/*.in.txt`、以及逐字捕获的程序输出证据件（`R2_50` / `R2_51`）
  按「只增不改」铁律**保持原样**；可追溯性由 `R4_10` §3 的映射表承担。
- 唯一随本轮一并调整的产品侧文本是 `lang/{zh,eng}.properties` 里三处用户可见文案
  （`opt.modelstrong` / `opt.scorecard` / `tier.sameSrc`），zh / eng 键对称不变。
