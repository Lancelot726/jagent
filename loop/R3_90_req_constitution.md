# 需求宪法 · R3 修订 · jagent

> 主体见 `R1_90_req_constitution.md`（R1 定稿件，只读，不回改）。
> 中间层见 `R2_90_req_constitution.md`（R2 修订页，只读，不回改）。
> 本文件只登记 **R3 起生效的修订**；三者冲突时以本文件为准。

采"修订页"而非整份复制（理由见 `R2_90` 开篇）：宪法是项目级唯一裁定依据，
整份复制会产生多份口径，只改其一会造成矛盾裁定依据。
按轮留痕的仍只有 **进度图 / 流水 / 台账 / 冻结清单** 四件。

## 修订 1：机制标签归入 L1（§3.5 的展开，非新增约定）

**问题**：R1 起，机制标签（竞价 / 拍卖 / 信誉 / 预算 / 利润 / 控制论 / 压缩 / 降级 / 路径互斥 / 执行图）
被放进了 `lang/*.properties`，即 **L2 层**——它们随用户语言变，中文档显示中文、英文档显示英文。

**判定**：这批标签**不是面向用户的散文，是内部协议词汇**，按硬约定 #5 本应属 L1
（内部固定英文 + 极强缩略）。放进 L2 是层次归属错误。

**修订**：这批标签固定为**英文**，取自"含义泛指的词汇"，**不带明确学科联想**。
不随 `--user-lang` 变化。面向用户的语言只作用于提示语、帮助文本、错误说明等真正的散文部分。

**幅度限定**（作者 2026-09-20 裁定）：**只改终端显示文字**。
代码类名（`Auction` / `Budget` / `Governor` 等）、lang 键名、`README.md`、`docs/` **一律不动**；
`loop/` 过程文件里的学科表述保留——那是过程记录，不是产品界面。

**替换范围**：作者原选"最带学科色彩的少数几个"，随后追加"对账单整块显然都要改掉"。
最终为 **9 个词**：竞价 / 拍卖 / 中标 / 信誉 / 预算 / 控制论 / 利润 / 机制对账 / 对账单。
其余（工具 / 步数 / 压缩 / 降级 / 路径互斥 / 执行图 / 轮次 / 结果）本来就中性，保持现状。

**因该批标签属 L1，zh 与 eng 两档取值相同**——对账单整块不再随 `--user-lang` 变化，
也不再出现中英混排。替换表见 `R3_10` §2。

**注意**：本条改的是**呈现**，不是**机制**。博弈论/经济学/工程经济学/控制论
仍按宪法 §1 直接作用于运行时，其行为、判定逻辑与证据（`R2_50` / `R2_51`）不变。

## 修订 2：取用"终端 raw mode 行编辑"推迟项（限基础版）

R1 宪法 §5 把"终端 raw mode 行编辑"列为推迟项，R2 又整体推迟。**R3 取用**，
但作者 2026-09-20 裁定**只取基础版**：

| 项 | 本次做 | 明确不做 |
|---|---|---|
| 入口 | **不带参数启动即进 REPL**（作者裁定） | — |
| 输入 | `> ` 提示符 + 读一行跑一行，循环到退出 | 方向键历史、行内光标编辑、Home/End、Tab 补全 |
| 模式 | **无模式**——`chat` 已取消，只剩 run，故不加模式标记 | 用上下键切模式（属 raw mode） |

即 R1 宪法原话里的"raw mode 行编辑"**本轮只实现其一半**（有输入循环，
无 raw mode 行编辑、无方向键）。完整版（接管终端原始模式）仍属推迟项，待作者另行下令。

**修订过程留痕**：本条的"模式"一格曾按作者原话写成「提示符前带模式标记（如 `[run]`），
可切换到 `chat`」；作者随后两次追加裁定 ——「感觉chat功能可以直接取消 既然它不读文件
默认就是run」与「提示符前都不用加[run]因为去除chat以后默认就是run」——
把这一格收缩为**无模式、无标记**。同一批裁定使 `chat` 子命令整体取消。

**连带影响**：无参数启动的现有行为（打印帮助后退出）被 REPL 取代；
`chat` 子命令消失，帮助行与 `cmd.chat` 键一并删除；README 与断言须同步（均已同步）。

**理由**：先把"可以反复敲命令"这件事做出来并固定住；raw mode 要自己处理跨平台按键字节，
体量与风险都大得多，不宜与显示缺陷修复捆在同一轮。

## 修订 3：执行图不再在节点上承载长摘要

**问题**：节点摘要在两处被先后截断（`Agent.summarize` 截 60 → `GraphView.clip` 截 48），
末句必被切；即便放宽上限，把模型整段回复塞进树节点也不合图的本意。

**修订**：**树形图只画结构与状态**（节点 / 状态字形 / 耗时），不再承载模型回复的长摘要；
模型回复改为**运行结束时统一给一段总结**。

**边界**：工具节点的短结果（如 `wrote 11 bytes`）仍可保留在节点上——它们是"该节点做了什么"的
最小事实，不是长散文。判定标准是"能否一行说完"，不是固定字数。

## 修订 4：进化论项暂缓（§1 表述不动）

作者 2026-09-20：「进化论的暂时删掉」。

**修订**：进化论基因组与变异算子**从待办中移除，暂缓（无期限）**。
宪法 §1 的项目定义表述（含"进化论"字样）**维持原文不动**——作者未要求改宪法，
本条只是不再把它列为待办项。

**影响**：R1/R2 均未开工此项，故对已交付内容无影响。

## 修订 5：「本地记忆」的语义（契约补充）

**问题**：R1 起就宣称"本地记忆"，实现上 `work/episodes.log` **只写不读**；
`facts.md` 依赖模型主动调用 `remember` 才写，`summary.md` 只在**压缩触发**时写。
实测中 `compress: 0 events` 且模型未调 `remember`，于是 `recall` 恒返回 `(memory is empty)`，
第二轮对话形同失忆。作者 2026-09-20：「我们确实强调本地记忆 但是每次第二次对话都像是失忆了」。

**修订**：本地记忆的契约明确为**两条同时成立**：

1. **落盘回灌** —— 每轮收尾把「目标 / 用了哪些工具 / 得到什么结论或卡在哪」写进 `work/`，
   下次启动或下一轮自动读回并注入系统提示。**不依赖模型主动调用工具**。
2. **会话内上下文** —— REPL 同一进程内，后续轮次的模型请求携带前几轮的用户消息与助手回答；
   进程退出后由第 1 条兜底。

**不改**：`work/` 的文件布局与既有 `remember` / `recall` 工具的语义不变。
本条是**补上缺失的读写通路**，不是替换既有机制。

## 修订 6：面向终端的两条呈现约定（§3.5 的展开）

**问题**：模型回复原样进终端，Markdown 记号（`**`、``` 围栏```、行首 `-` / `#`）直接可见；
收尾打印的是模型回复原文而非运行级总结；且同一段内容被打印两遍。

**修订**：

1. **终端输出层剥掉 Markdown 记号**，保留层次的读感（代码块内容缩进保留，列表项换中性项目符）。
   判据是「记号不留，层次不丢」。
2. **每轮收尾给一段运行级总结**：目标、用到的工具、结果（成功 / 失败 / 中止）、结论。
   失败时须说明**卡在哪一步、已取得什么、下一步建议**。
3. **同一内容不重复打印**：模型正文只在收尾打印一次，不再流式重放。

**边界（重要）**：改的是**呈现**。剥离**只作用于终端显示**；
进 `convo` 与进 `work/` 落盘的仍是模型原文 —— 否则会污染压缩摘要与记忆两条链路的输入。

**本条的修订（2026-09-20，G3 现场二次追加，见 `R3_10` §2.4）**：
第 2 款原先要求"每轮收尾**另给一段**运行级总结"，实现出来就是 `answer` 之后又叠一个四行块 ——
作者在现场否掉了它。现改为：**收尾只有 `answer` 一段，三种结局都在这一段内交付**
（成功 → 模型答复；失败 → 停在第几步 + 原因 + 下一步建议；中止 → 截至第几步没有最终答复）。
第 2 款要的目标（收尾必须说清结局、失败也要说清卡点）**一条不减**，只是不再单设载体。
同时约定：运行过程默认只打印 `step` / `tool` / `result` 三类行，工具参数只摘要显示，
机制自证类输出（竞价行 / `[quota ...]` / `summary` 对账块）默认为静默，由 `--scorecard` 显式索取；
**关闭打印不等于关闭记账**，`work/scorecard.txt` 与 `work/runs.md` 照常写盘。

## 修订 7：本机环境须告知模型（§3.5 的展开）

**问题**：系统提示里**没有任何环境信息**（操作系统、外壳、工作目录、编码），
模型只能按通识猜，于是在 Windows 上写出 `date '+%Y年%m月%d日'` 与 `python3`：
前者在 CMD 里会进入交互式提问并卡死，后者在本机不存在。

**修订**：系统提示须带**本机环境事实**（操作系统 / 外壳 / 工作目录 / 控制台编码），
`bash` 工具的说明亦须标明实际外壳。**这是告知事实，不是注入策略** ——
不预设厂商、不给命令模板，仍由模型自行决定怎么做。

**配套（工具健壮性，非宪法层）**：子进程 stdin 立即关闭，避免交互式命令把整轮拖到超时；
输出按控制台原生编码解码，消除 GBK/UTF-8 错配产生的乱码。

## 修订 8：步数上限由写死改为配置项

**问题**：单轮步数上限是**两处写死的字面量** —— 根 agent `16`、子 agent `8`，
要改必须改码重编。作者 2026-09-20 问「怎么让步数无上限」。

**修订**：上限归到配置键 `max-steps`（环境变量 `JAGENT_MAX_STEPS`），默认 **16**，
**根 agent 与子 agent 共用同一个值**；设 `0` 或负数表示**不限步数**。

**实现约束**：不得用 `Integer.MAX_VALUE` 当"无上限"的替身 ——
`step++` 会在该值处溢出为负数，使 `step <= maxSteps` 反而恒真，
必须用哨兵判断（`maxSteps <= 0 || step <= maxSteps`）。

**已知边界（作者知悉并选择暂不处理）**：上限是**当前唯一的循环出口**。
`Budget` 只记账并影响出价，`Governor` 的 `open` 跳闸标志在 `Agent.run` 中未被读取，
两者都**不中止**循环。因此"不限步数"只承诺不给自设的截止，
**不承诺兜住不收敛的任务**；补第二道硬闸（无进展即停 / 预算耗尽即中止）
列入 R4 待办，与本轮收缩后的"熔断与中止策略"一项合并考虑。
