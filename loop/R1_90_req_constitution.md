# 需求宪法 · jagent

> 唯一裁定依据：什么算本项目、交付什么、哪些硬性约定不可破。
> 每次收到新意见先读本文件，再判断该意见是否越出范围。

## 1 项目定义

用 Java 25 实现**终端 CLI coding agent**（对标 Claude Code / Pi）。
差异化不在于"换语言重写"，而在于**把六条运行时机制做成可观察的工程实现**：
模型路由、资源管理、ROI 判定、自适应并发控制、执行图、自动化闸门
**直接作用于运行时**，不是写在文档里的口号。

## 2 一句话主张

以纯 JDK 零依赖的 Java 实现，挑战 Go / Rust / C++ 编写的同类工具，
在**启动速度、产物体积、常驻内存**上进入同一量级竞争。

## 3 硬性约定（破了就是越界）

| # | 约定 | 理由 |
|---|---|---|
| 1 | **纯 JDK 零依赖**，运行时不得引入任何第三方 jar | native 编译、体积、启动速度的前提 |
| 2 | **不使用任何 preview 特性** | 会锁死 JDK 版本并拖累 native-image |
| 3 | 源码**不写注释**，实现取最小 | 作者工程约束；规则写进 `docs/` 而非代码 |
| 4 | 密钥**不进代码、不进 git** | 安全 |
| 5 | **语言分两层：L1 内部固定英文+极强缩略；L2 面向用户由用户首启选定（Zh/Eng）**，见 §3.5 | 作者工程约束 |
| 6 | 每阶段跑通再进下一阶段 | 避免一次性堆积不可运行代码 |

## 3.5 语言槽位（硬约定 #5 的展开）

**`[]` 里的语言是用户可选项，不是常量。** 任何文件（含 `loop/` 内的过程文件）
不得把"中文"或"英文"写成面向用户语言的固定值，只能表述为"用户选定语言"。

| 层 | 语言 | 可否选择 | 理由 |
|---|---|---|---|
| L1 内部 | 英文 + 极强缩略 | 不可选 | 缩略语法只在英文成立；内部追求最短 token |
| L2 面向 | `{{user_lang}}` ∈ {Zh, Eng} | 首启选定 | 交付物与问答要让用户读得舒服 |

- 提示词只有**一份模板**，槽位写作 `{{user_lang}}`，装配时替换为 `Lang.tag()`。
- 界面串按语言分文件（`resources/lang/<code>.properties`），**加语言 = 加文件 + 枚举 + 映射**。
- 解析优先级：`--user-lang` > `JAGENT_USER_LANG` > `work/jagent.properties` > 首启交互选择 > 默认 Zh。
- 详细设计见 `R1_30_design_lang_slots.wip.md`。

**作用范围**：产品代码与资源、`loop/` 全部过程文件、README 与 `docs/`。
唯一例外是 `R1_03_style_prompt.in.txt` —— 它是只读输入原稿，按"只增不改"铁律不动。

## 5 本期范围内 / 外

**R1 内**：ReAct 主循环与工具、终端 Unicode 图渲染、多 agent 并行、记忆与语义压缩、
模型路由（密封报价）、资源管理（预算与压缩 ROI）、自适应并发控制（并发闭环与熔断）、自动化（调度即受控对象）。

**R1 外（推迟 R2）**：自适应演化参数集与变异操作、GraalVM native 构建、
分层流程图布局（R1 只做 Unicode 树）、终端 raw mode 行编辑。
